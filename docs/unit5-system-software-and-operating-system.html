Unit V – System Software and Operating System

UGC NET Computer Science and Applications – Paper II

This unit covers system software, operating-system concepts, processes, threads, CPU scheduling, deadlocks, memory management, storage management, file systems, security, virtual machines, Linux, Windows, and distributed operating systems.

Part A – System Software

1. System Software

System software provides a platform and services for application programs.

Examples:

  • Operating systems
  • Compilers
  • Assemblers
  • Linkers
  • Loaders
  • Debuggers
  • Macro processors

System software works close to the hardware.

2. Machine Language

Machine language consists of instructions directly represented in binary form.

Example:

10110000 01100001

Advantages:

  • Directly executed by hardware
  • No translation required at execution time

Disadvantages:

  • Difficult for humans to write
  • Difficult to debug
  • Machine dependent

3. Assembly Language

Assembly language uses symbolic instructions instead of binary codes.

Example:

MOV AX, 10
ADD AX, 20

An assembler translates assembly language into machine code.

4. High-Level Languages

High-level languages are closer to human language than machine language.

Examples:

  • C
  • C++
  • Java
  • Python

Advantages:

  • Easier to write
  • Easier to maintain
  • More portable
  • Supports abstraction

Relocation adjusts address-dependent code or data when a program is placed at a particular memory location.

A program may contain relocatable addresses before loading.

12. Macros

A macro is a named sequence of instructions or source statements that can be expanded when used.

Example:

may expand into several instructions.

A macro processor performs macro expansion.

Advantages:

  • Reduces repeated source code
  • Improves source-level convenience

A debugger helps programmers find and analyze program errors.

Common debugger features:

  • Breakpoints
  • Step-by-step execution
  • Variable inspection
  • Stack inspection
  • Watch expressions
  • Call stack

Part B – Basics of Operating Systems

14. Operating System

An Operating System (OS) is system software that manages computer hardware and provides services to application programs.

Main responsibilities:

  • Process management
  • Memory management
  • File management
  • I/O management
  • Storage management
  • Protection and security
  • Networking
  • User interface

Examples:

  • Linux
  • Windows
  • macOS
  • Android

15. Operating System Structure

An OS can be organized using different structures.

Common approaches:

  • Simple structure
  • Layered structure
  • Monolithic structure
  • Microkernel
  • Modular structure
  • Hybrid structure

16. Monolithic Structure

Most OS services execute in a large kernel address space.

Advantages:

  • Efficient communication
  • Good performance

Disadvantages:

  • Large kernel
  • Less isolation between components

18. Microkernel

A microkernel keeps only essential services in the kernel.

Other services can run in user space.

Typical microkernel responsibilities:

  • Basic scheduling
  • Interprocess communication
  • Basic memory management

Advantages:

  • Modularity
  • Better isolation
  • Easier extension

Potential disadvantage:

  • Communication overhead can affect performance depending on implementation.

Part D – Process Synchronization

36. Process Synchronization

Synchronization coordinates processes or threads accessing shared resources.

It prevents incorrect results caused by uncontrolled concurrent execution.

37. Race Condition

A race condition occurs when the result depends on the timing or order of concurrent operations.

Example:

Two processes update the same bank balance simultaneously.

Without proper synchronization:

Initial balance = 1000

Process A reads 1000
Process B reads 1000

A writes 1100
B writes 900

Final = 900

The expected result may be 1000, depending on the intended operations.

38. Critical Section

A critical section is a part of a program where shared data or a shared resource is accessed.

Requirements for a correct critical-section solution:

  1. Mutual exclusion
  2. Progress
  3. Bounded waiting

39. Mutual Exclusion

Only one process can execute its critical section for the same shared resource at a time.

40. Progress

If no process is executing in its critical section, processes that want to enter should not be postponed indefinitely.

41. Bounded Waiting

A process should not wait forever after requesting entry into its critical section.

42. Peterson’s Solution

Peterson’s solution is a classical software solution for mutual exclusion between two processes.

It uses shared variables conceptually similar to:

flag[i]
turn

The flag indicates interest in entering the critical section.

The turn variable helps decide which process should enter.

Important limitation:

  • Classical Peterson’s solution is for two processes and relies on assumptions about memory operations that may not hold directly on modern hardware without appropriate memory-ordering considerations.

43. Semaphores

A semaphore is a synchronization variable accessed using atomic operations.

Two classic operations:

wait()
signal()

They are also commonly called:

P()
V()

Binary Semaphore

Can represent:

0 or 1

It can be used for mutual exclusion.

Counting Semaphore

Can represent a non-negative count of available instances of a resource.

44. Synchronization Example

Suppose only one process can access a printer at a time.

wait(printer)

Use printer

signal(printer)

Part E – Threads

45. Thread

A thread is a unit of CPU execution within a process.

Threads of the same process can share:

  • Code
  • Data
  • Files
  • Address space

Each thread normally has its own:

  • Program counter
  • Registers
  • Stack

46. Process vs Thread

Process Thread
Independent execution environment Execution unit within a process
More expensive to create Usually cheaper to create
Separate address space normally Threads share process address space
IPC can be expensive Communication can be easier through shared memory

47. Multicore Programming

A multicore processor has multiple CPU cores.

Multithreading can allow work to run in parallel on multiple cores.

Challenges:

  • Identifying parallel tasks
  • Synchronization
  • Load balancing
  • Data dependencies
  • Debugging

48. Multithreading Models

Common models:

  1. Many-to-one
  2. One-to-one
  3. Many-to-many

Many-to-One

Many user threads map to one kernel thread.

T T T T
 \| |/
  Kernel Thread

A blocking system call can block all user threads, and true parallelism on multiple cores is not obtained through that single kernel thread.

One-to-One

Each user thread maps to one kernel thread.

T → K
T → K
T → K

Allows greater parallelism but may have higher overhead.

Many-to-Many

Many user threads are multiplexed over a set of kernel threads.

49. Thread Libraries

Thread libraries provide APIs for creating and managing threads.

Examples:

  • POSIX Pthreads
  • Windows threads
  • Java threading APIs

50. Implicit Threading

Implicit threading allows compilers, runtime systems, or libraries to manage much of the thread creation and scheduling.

Examples/concepts:

  • Thread pools
  • OpenMP
  • Grand Central Dispatch
  • Task-based parallelism

51. Threading Issues

Important issues:

  • Thread cancellation
  • Signal handling
  • Thread pools
  • Thread-local storage
  • Fork and exec semantics
  • Synchronization

Part F – CPU Scheduling

52. CPU Scheduling

CPU scheduling selects a process/thread from the ready queue for CPU execution.

Goals can include:

  • High CPU utilization
  • High throughput
  • Low turnaround time
  • Low waiting time
  • Low response time
  • Fairness

53. Scheduling Criteria

CPU Utilization

Percentage of time the CPU is busy.

Goal:

Maximize

Throughput

Number of processes completed per unit time.

Goal:

Maximize

Turnaround Time

Time from process submission to completion.

Turnaround Time =
Completion Time - Arrival Time

Waiting Time

Total time spent waiting in the ready queue.

Response Time

Time from request submission until the first response.

54. Preemptive vs Non-Preemptive

Preemptive

The OS can interrupt a running process and assign the CPU to another process.

Non-Preemptive

A running process normally keeps the CPU until it terminates, blocks, or voluntarily gives up the CPU.

55. First-Come, First-Served

FCFS schedules processes according to arrival order.

Example:

P1 → P2 → P3

Advantages:

  • Simple
  • Easy to implement

Disadvantage:

  • Can produce large waiting times
  • Convoy effect

56. Shortest-Job-First

SJF selects the process with the smallest CPU burst.

Advantages:

  • Minimum average waiting time under ideal assumptions for non-preemptive scheduling

Disadvantages:

  • Requires burst-time prediction
  • Long processes may starve

57. Shortest-Remaining-Time-First

SRTF is the preemptive version associated with shortest-job scheduling.

The process with the smallest remaining CPU burst is selected.

58. Priority Scheduling

Each process receives a priority.

The scheduler selects a process according to priority.

A problem can be:

Starvation

A common solution is:

Aging

Aging gradually increases the priority of waiting processes.

59. Round Robin

Round Robin uses a time quantum.

Example:

P1 → P2 → P3 → P1 → P2 → ...

Advantages:

  • Good response for interactive systems
  • Fair CPU sharing

Important parameter:

Time quantum

If the quantum is too small:

  • Many context switches

If it is too large:

  • Behavior approaches FCFS

60. Multilevel Queue

The ready queue is divided into separate queues.

Example:

System processes
Interactive processes
Batch processes

Each queue may use its own scheduling policy.

61. Multilevel Feedback Queue

Processes can move between queues based on their behavior and scheduling rules.

It can provide flexible scheduling but is more complex to configure.

62. Scheduling Algorithm Comparison

Algorithm Preemptive? Important point
FCFS No Arrival order
SJF No Shortest burst
SRTF Yes Shortest remaining time
Priority Can be either Priority based
Round Robin Yes Time quantum
Multilevel Queue Depends Separate fixed queues
MLFQ Usually preemptive Processes can move between queues

63. Thread Scheduling

Thread scheduling may be performed at:

  • User level
  • Kernel level

Many-to-one systems can schedule user threads within a process while the kernel schedules the process.

64. Multiple-Processor Scheduling

In multiprocessor systems, scheduling involves multiple CPUs/cores.

Important approaches:

  • Asymmetric multiprocessing
  • Symmetric multiprocessing

Asymmetric Multiprocessing

One processor may handle scheduling/system activities while others execute assigned work.

Symmetric Multiprocessing

Each processor can perform scheduling and other OS activities.

Important issue:

Load balancing

65. Real-Time CPU Scheduling

Real-time systems have timing requirements.

Two broad categories:

Hard Real-Time

Missing a deadline can cause unacceptable failure.

Soft Real-Time

Missing a deadline reduces quality but may not cause total system failure.

Important algorithms/concepts:

  • Rate Monotonic Scheduling
  • Earliest Deadline First

Rate Monotonic

Static priority based on task period.

Shorter period:

Higher priority

Earliest Deadline First

The task with the earliest deadline gets higher scheduling priority.

Part G – Deadlocks

66. Deadlock

A deadlock occurs when a set of processes are permanently waiting for resources held by one another.

Example:

P1 holds R1 → waits for R2
P2 holds R2 → waits for R1

67. Four Necessary Conditions

Deadlock requires all four conditions:

  1. Mutual exclusion
  2. Hold and wait
  3. No preemption
  4. Circular wait

Mutual Exclusion

At least one resource is non-shareable.

Hold and Wait

A process holds resources while waiting for additional resources.

No Preemption

Resources cannot be forcibly taken away under the model.

Circular Wait

A circular chain of waiting processes exists.

68. Resource Allocation Graph

A resource allocation graph can represent processes and resources.

P1 → R1
R1 → P2
P2 → R2
R2 → P1

A cycle may indicate deadlock under appropriate assumptions, especially when each resource type has a single instance.

69. Methods for Handling Deadlocks

Four general approaches:

  1. Deadlock prevention
  2. Deadlock avoidance
  3. Deadlock detection and recovery
  4. Ignore the problem in some systems when appropriate

70. Deadlock Prevention

Prevention ensures at least one necessary condition cannot hold.

Examples:

  • Break hold-and-wait
  • Allow preemption where possible
  • Impose a total ordering on resources to prevent circular wait

71. Deadlock Avoidance

Avoidance requires information about future resource needs.

The system checks whether granting a request keeps the system in a safe state.

72. Banker’s Algorithm

The Banker’s algorithm is a classical deadlock-avoidance algorithm.

Important concepts:

Available
Max
Allocation
Need

Formula:

Need = Max - Allocation

A state is safe if there is an order in which every process can obtain its remaining resources and finish.

73. Deadlock Detection

A system may allow deadlocks and periodically detect them.

For multiple instances of resources, detection uses data such as:

Available
Allocation
Request

74. Deadlock Recovery

After detecting deadlock, possible actions include:

  • Terminating processes
  • Preempting resources
  • Rolling back selected processes

Part H – Memory Management

75. Memory Management

The OS manages allocation and deallocation of main memory.

Responsibilities:

  • Track memory use
  • Allocate memory
  • Deallocate memory
  • Provide address translation
  • Protect processes

76. Contiguous Memory Allocation

Each process occupies one contiguous block of memory.

Approaches include:

  • Fixed partitioning
  • Variable partitioning

Problems:

  • Internal fragmentation
  • External fragmentation

77. Internal Fragmentation

Allocated memory contains unused space inside the allocated region.

78. External Fragmentation

Free memory exists, but it is divided into small non-contiguous holes.

79. Swapping

Swapping temporarily moves a process between main memory and secondary storage.

87. Page Replacement

When no free frame is available, the OS may replace an existing page.

Important algorithms:

  • FIFO
  • Optimal
  • LRU
  • Second-Chance/Clock

88. FIFO Page Replacement

FIFO replaces the page that entered memory first.

Advantage:

  • Simple

Disadvantage:

  • Can suffer from Belady’s anomaly

89. Optimal Page Replacement

Replaces the page that will not be used for the longest time in the future.

It gives the minimum possible page faults for a reference string under the standard model.

Limitation:

  • Future references are not known in actual execution

It is mainly used as a benchmark.

90. LRU

LRU means Least Recently Used.

It replaces the page that has not been used for the longest time in the past.

93. Thrashing

Thrashing occurs when a system spends excessive time handling page faults and swapping pages rather than executing useful work.

97. Disk Scheduling

Disk scheduling determines the order in which disk requests are serviced.

Important algorithms:

  • FCFS
  • SSTF
  • SCAN
  • C-SCAN
  • LOOK
  • C-LOOK

98. FCFS Disk Scheduling

Services requests in arrival order.

Advantage:

  • Simple

Disadvantage:

  • May result in large head movement

99. SSTF

SSTF means Shortest Seek Time First.

The request closest to the current head position is selected.

Advantage:

  • Can reduce average seek distance

Disadvantage:

  • Possible starvation of far-away requests

100. SCAN

SCAN moves the disk head in one direction, servicing requests, then reverses direction.

It is often called the elevator algorithm.

101. C-SCAN

C-SCAN services requests in one direction.

After reaching one end, the head returns to the beginning without servicing requests on the return path.

102. LOOK and C-LOOK

LOOK stops at the last pending request in a direction rather than moving all the way to the physical end.

C-LOOK is the circular version.

103. Disk Scheduling Comparison

Algorithm Main idea

C-SCAN Circular scan
LOOK SCAN without going to physical end

RAID 0

Striping without redundancy.

  • High performance

Disadvantage:

  • No fault tolerance

RAID 1

Mirroring.

Disk 1 = Data

Advantage:

  • High redundancy

Disadvantage:

  • Uses additional storage

RAID 5

Striping with distributed parity.

Can tolerate failure of one disk in the standard RAID 5 configuration.

RAID 6

Striping with double distributed parity.

Can tolerate failure of two disks in the standard configuration.

173. Common Mistakes

Process vs Program

Program  → Passive instructions
Process  → Program in execution

Process vs Thread

Process → Independent execution environment
Thread  → Execution unit within a process

Paging vs Segmentation

Paging      → Fixed-size pages
Segmentation → Logical variable-size segments

Internal vs External Fragmentation

Internal → Wasted space inside allocated block
External → Free space scattered outside allocated blocks

Compiler vs Interpreter

Compiler    → Translation toward target code
Interpreter → Execution through interpretation

Linker vs Loader

Linker → Combines object files/libraries
Loader → Loads executable into memory

Deadlock Prevention vs Avoidance

Prevention → Break a necessary condition
Avoidance  → Grant requests only if state remains safe

Starvation vs Deadlock

Starvation → Process waits indefinitely because others keep getting service
Deadlock   → Processes wait for one another in a cycle

Semaphore vs Mutex

A mutex is generally used as a mutual-exclusion lock associated with ownership semantics in many systems.

A semaphore is a synchronization/counting mechanism and may represent multiple resource instances.

FCFS vs Round Robin

FCFS → Arrival order
RR   → Time quantum
